CLAUDE.md — Mozaic Cafe, Bar & Kitchen

Context file for Claude Code sessions on this project. Read this before making changes.

Project purpose

Portfolio site built for a real cafe (Mozaic Cafe, Bar & Kitchen, Mabalacat, Pampanga) whose owner's family the maintainer personally knows. Dual goal: strong portfolio piece AND a genuine improvement over their existing official site, not a from-scratch pitch to a business with nothing.

Stack
Next.js 16 (Turbopack) + Tailwind v4
TypeScript, App Router
Solo maintainer (PTF50 group project — teammates may join). Tests: `npm test` (matcher rules) and `npm run test:ai` (matcher with real model); no UI test suite
Fonts: League Spartan (display, headings, utility labels; variable axis) and Poppins (body), nothing else. Per the owner's brand style sheet, headers set at letter-spacing -0.05em (`tracking-moz`), body at 0. The style sheet also names NATS for sub-headers, but it isn't in next/font/google's catalogue. Logo is image-based (see Logo usage below), not a text wordmark.
Icons: lucide-react (plain outline icons, only where they aid recognition — tab bar, segmented control, contact rows). Brand-platform icons stay in components/icons/BrandIcons.tsx.
Motion: CSS only. Remotion was removed in Nov 2026 with the hero mosaic; don't reintroduce it.
AI: @huggingface/transformers 4 (Transformers.js) — PTF50 final-project feature, see "Mood Matcher" below.
package.json is "type": "module"; Node 22+ runs the .ts scripts and tests directly (native type stripping), which is why lib/matcher imports use explicit .ts extensions (tsconfig allowImportingTsExtensions).
Deployment target: Vercel
Current architecture state
Real menu data hardcoded in lib/mockData.ts, transcribed from the owner's actual published menu (linktr.ee/moz.cbk)
Fully static site — no backend, no database, no API routes, no env vars. The admin/Supabase scaffold (app/admin/*, app/api/menu/*, lib/auth.ts, lib/supabase.ts, components/Admin*.tsx, .env.local.example, @supabase/supabase-js, the .brutal-*/.halftone-blue/.stamp-badge CSS shims and the --color-brand-blue/navy/black/white aliases) was CUT in Nov 2026 for the PTF50 project: it was inert (fake localStorage auth, 501 write routes, /admin 404ing), and the spec rewards a small, keyless, explainable app. Menu edits = edit lib/mockData.ts, then `npm run embed`. Don't reintroduce an admin panel or a database as part of unrelated work; if real menu management is ever wanted, treat it as its own decision (real auth + RLS from day one, never a client-side flag).
Baseline security headers (X-Frame-Options, X-Content-Type-Options, Referrer-Policy, CSP) are set in next.config.ts. The CSP's script-src needs 'unsafe-inline' because Next.js App Router streams RSC payloads via inline scripts — locking that down further requires a nonce-based CSP via middleware.ts, which is a deliberate follow-up, not done yet.
The CSP ALSO carries three Mood Matcher additions that must not be "hardened" away: 'wasm-unsafe-eval' (WebAssembly compile only, not JS eval), worker-src 'self' blob:, and connect-src to huggingface.co / *.huggingface.co / *.hf.co (model weights). There is deliberately NO blob: in script-src and no jsdelivr: the ONNX Runtime wasm is self-hosted at /ort (scripts/copy-ort.ts, run by predev/prebuild, output gitignored) and lib/matcher/worker.ts sets env.useWasmCache = false so Transformers.js imports it directly instead of via a blob: URL.

Mood Matcher (/match) — PTF50 AI feature
Customer describes taste/budget/company in English or Taglish; an embedding model running in the browser ranks the menu. Hybrid by design, and the split must be kept: lib/matcher/parseQuery.ts extracts hard constraints with rules (budget, per-person, party size, "no X", alcohol intent) and strips them from the text the model sees, because embeddings handle negation and numbers badly; lib/matcher/rank.ts filters by those rules, then score = cosine(query, item) + 0.04 x requested tags - 0.06 for canned drinks not named, then builds a variety-first budget basket for groups. Model: Xenova/all-MiniLM-L6-v2 (q8) via Transformers.js in a module Web Worker (lib/matcher/worker.ts), driven by lib/matcher/useMatcher.ts. Item vectors are precomputed by `npm run embed` into lib/matcher/menuEmbeddings.json (stamped with a menu hash; the browser warns when stale). Any change to lib/mockData.ts menu items or lib/matcher/menuTags.ts REQUIRES `npm run embed`, then `npm test` (rules, no model) and `npm run test:ai` (real model). lib/matcher/menuTags.ts is an owner-unreviewed DRAFT (OWNER_REVIEWED = false): tags come only from published names/descriptions; anything unconfirmed is a `maybe` tag, which counts as present when excluding and absent when matching. Never promote a `maybe` to a tag without the owner's confirmation. lib/matcher/config.ts holds FEEDBACK_FORM_URL (empty = feedback link hidden). PTF50 deliverables live in docs/ (SETUP, PROPOSAL, USER_TESTING, COST, PROMPT_LOG); docs/PTF50_REFACTOR_PLAN.md is a gitignored local note.

Design standard

Always apply strong, intentional design judgment when building or revising any page — commit to a specific bold aesthetic direction, avoid generic AI-default patterns (excess whitespace, centered-everything-narrow-column layouts, under-filled desktop views). Desktop breakpoints (1024px+) must be treated as a first-class layout, not a stretched mobile view — use multi-column layouts, larger imagery, and intentional use of horizontal space. If a frontend-design skill is available, use it; otherwise apply these principles directly. Exception: /match is mobile-first — its main entry is a phone scanning the counter QR code — though it still gets a two-column desktop layout.

Art direction (Nov 2026, branch feature/ui-refactor). Two passes: a "blue sticker" refactor from four mood boards (Woofers, Times Bakery), then a follow-up art-direction pass after the user found the result clunky: giant bleeding wordmark, sticker/seal/squiggle clutter, and the Remotion star-grid hero, which the user explicitly rejected ("get rid of it or anything of that sort"). The second pass follows the user's brief: bold but controlled, editorial, authentic imagery, every decorative element earning its place. Rules:
- PALETTE: `--moz-blue` #3866bb (pubmat-sampled, kept over the brief's suggested #2456B8), white, and `--moz-cream` #f1ede3 (`.moz-paper`, flat; the crumple texture is gone) to break up blue. `--moz-ink` #24479a for small text. No black anywhere (the black frame is retired). No navy/grey ramp. The brief's optional pink accent was NOT adopted; it doesn't appear in any mozaic asset.
- SECTION RHYTHM: alternate blue / cream / white. Not every section is a blue card with white text.
- TYPE: two families. League Spartan for display (`moz-display`), section (`moz-h2`), card titles (`moz-h3`) and the utility label (`.moz-micro`, the ONLY uppercase). Poppins for body. These are @utility classes in globals.css. No italics, no wide tracking, no Bagel Fat One (removed).
- BUTTONS: `moz-btn moz-btn-base` + one of `moz-btn-solid` / `moz-btn-line` (light grounds) or `moz-btn-white` / `moz-btn-white-line` (blue grounds). 48px pill. Platform-brand buttons (OrderButtons, ContactButtons) keep platform colours.
- FLAT: 2px outlines (`--moz-line`), no shadows, no gradients, no blur, no tilts, no stickers. `.moz-lift` brightens; it never moves.
- MOTIF: the StarMark as label/bullet punctuation, plus `BrandBand` (static repeating name strip, once, above the footer). `Ticket` survives for the menu happy hour and matcher basket. Seal and Squiggle are deleted; don't bring back seals, squiggles, sparkles, mascots or stickers.
- HERO: copy + CTAs on the left; the real cafe/kitchen/bar posters fanned as the one focal object on the right (native ratio, never cropped), with a facts rail (hours / address / delivery) along the bottom. No giant logo, no Remotion, no generated tile/grid animation.
- IMAGERY: only real, text-free photos count as photography. Pubmats with baked-in text may appear only shown whole as artwork (catering page), never cropped as a photo. docs/ASSETS_NEEDED.md is the audit and the shopping list for the owner.
- Navbar: solid white, blue bottom rule, active link = underline + star, "Order" CTA → /#order. Fixed h-16: MenuTabs' sticky offset depends on it. Tab bar: white, blue top rule, Match raised in the centre.
- Grouped lists (.moz-group) keep the blue label-strip header and dashed rules; segmented control unchanged.

Google reviews marquee (components/ReviewMarquee.tsx)
Rendered layout-level in app/(site)/layout.tsx, between <main> and <Footer />, so it appears on every page. Data lives in lib/mockData.ts → reviews (typed as Review in lib/types.ts) — these are REAL reviews, hand-transcribed verbatim from the Google Maps listing (https://maps.app.goo.gl/hgtcJ11VabbjQv486, also SOCIAL_LINKS.googleMaps) in Aug 2026, so the marquee is live. Add more only the same way — read and copy by hand; don't scrape or fabricate. The `date` fields are Google's relative wording and drift stale.

ReviewMarquee keeps its guard (renders nothing if every entry is placeholder-shaped) as a safety net. components/SocialFeed.tsx applies the identical rule to the post wall: the grid is hidden unless a socialPost has a real image_url, since those entries otherwise render as a feed whose links all point at the profile root. Keep both guards if you touch either file.
CSS gotcha worth remembering: custom classes in globals.css (.moz-btn, .animate-marquee, etc.) are unlayered CSS, while Tailwind's own utilities live inside @layer utilities. Unlayered CSS always beats layered CSS regardless of specificity — so a Tailwind arbitrary-value utility like hover:[animation-play-state:paused] can never override a plain custom class's shorthand property (this broke the marquee's pause-on-hover during initial implementation). Fix is to write the hover state as a plain rule in globals.css next to the base class (see .animate-marquee:hover), matching how .moz-btn:hover already does it — not as a Tailwind variant on the element. The same trap bit the Apple layer once: an unlayered `a.moz-group-row { display: block }` overrode the `flex` utility on every tappable row — so primitives in globals.css must never set `display` (or other layout) on elements that utilities lay out.
